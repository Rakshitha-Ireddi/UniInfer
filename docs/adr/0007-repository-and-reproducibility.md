# ADR-0007: Repository layout, committed results, environment

- **Status:** Accepted
- **Date:** 2026-11-10

## Context
The project should work as a library people can import, a research record people can audit, and an
open-source project people can contribute to.

## Decision
- **`src/uniinfer/`** is an installable package with no experiment-specific code: `compression`,
  `runtime`, `controller`, `metrics`, `data`.
- **`experiments/<name>/`** holds thin, numbered scripts that use the package. Every figure and table is
  regenerated by a script.
- **`results/<version>-<name>/`** holds committed raw results (JSONL, features, metadata, text reports,
  about 6 MB for v0.1). Analysis and figures rerun on CPU without a GPU. Models, datasets and caches are
  never committed.
- **Environment:** `scripts/setup_env.sh` builds a `uv` venv in a work directory (no root or conda
  needed), with pinned torch 2.5.1/cu121 and transformers 4.51.3. Every results folder has a `*_meta.json`
  recording model, GPU, torch version and grid.
- **CI** runs ruff and the CPU unit tests on every PR. GPU correctness checks (`sweep.py --check`) run
  manually before each release and are noted in the changelog.

## Consequences
- Anyone can check our numbers from the committed JSONL in seconds.
- Repo size must be watched. Larger future sweeps should go to a GitHub Release asset or the HF Hub, with
  a download script.
